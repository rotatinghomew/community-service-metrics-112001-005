# 分阶段服务措施效果评估

供项目管理者使用：比较分期启动的新服务安排是否改善了办理体验，同时明确
**比较对象何时仍可作为对照、何时受到措施影响**，并给出估计的**不确定性**与
**适用范围**，而不是一个排名。

## 运行

```bash
python3 -m service_eval check --sources fixtures     # 校验资料
python3 -m service_eval draft --sources fixtures     # 打印方案草案
python3 -m service_eval serve  --sources fixtures --state data/state.json --port 8000
```

打开 `http://127.0.0.1:8000/`。只用 Python 3.11 标准库，无第三方依赖。
`demo/` 是一份 8 网格、94 条结果记录的演示资料，可直接用 `--sources demo` 启动。

命令行也可以在不打开网页时重算：

```bash
python3 -m service_eval freeze  --sources demo --state data/state.json \
    --protocol plan.json --reason "初次冻结"
python3 -m service_eval analyze --sources demo --state data/state.json --save
```

## 设计要点

**先冻结，后看结果。** 结果口径（按期办结数 / 已成熟事项数）、比较时段、
对照资格规则、启动当月与暂停月处理、成熟度门槛、区间宽度上限都必须先写入
方案。方案存为只增不改的版本；修订必须写理由，并列出改了哪些字段。没有冻结
方案时分析接口直接拒绝（`409`）。方案不接受任意字段，因此不存在“按结果挑
网格”“悄悄换口径”的开关。

**对照资格逐月判定。** 网格从启动当月（按预设规则）起不再作为对照；退出后
也不会自动回到对照。暂停、不足月、启动当月分别有独立状态，都可在方案里预先
规定如何计入。每个网格月份的判定理由、对照池的每次增减都列在“对照资格与覆盖”
页，便于负责人核查。

**未成熟事项不计入失败。** 分母只含已成熟事项；受理数与成熟数之间的差额单独
展示。期末成熟比例低于预设下限时不给结论。

**不确定性与适用范围。** 主估计按成熟事项（可再乘人口）加权汇总；区间用留一
网格刀切法（t 分布），网格不足以去掉任一网格时明确写“聚类区间不可估计”，
同时给出标注为低估的合并二项区间。适用范围列出实施网格覆盖的人口比例、城乡
类型、对照中临近自身启动与始终未启动的份额、单对照月份。

**同期因素。** 冲击逐条列出并标为“与措施无法区分”，另给排除冲击月份的敏感性；
季节与月份完全重合，报告直接说明无法分离，只能靠同月对照抵消共同季节影响。
另提供按城乡类型、规模的月份内回归调整作为辅助读数，并声明其区间未按网格聚类。

**结论门槛。** 只有同时满足预设的成熟事项数、可比月份数、区间宽度上限，且区间
不含 0、敏感性不改变方向时，才标记“可据此讨论下一步”；否则明确写“不能下结论”，
并给出“扩大 / 调整 / 继续观察”三种行动下应有的说明。报告附“不允许的读法”。

**修订与资料变化的影响范围。** 每次重算会与上一份报告比较，列出变化的方案字段、
实施/对照集合、纳入月份、状态改变，以及判定发生变化的网格月份。

## 资料

`fixtures/`（4 网格、6 条结果）与 `demo/`（8 网格、94 条结果）的字段含义见
`DATA.md`。空字符串表示来源未给出该事实，不解析为零或否；缺失月份表示无观测。
投递的表格里有计数口径矛盾（如按期数大于成熟数）时，该网格月份不进入估计、
保留在覆盖表中并列入“资料核查”，不会被当成失败或被悄悄修正。

## 目录

```
service_eval/  domain.py 解析与暴露状态   design.py 对照资格审计
               protocol.py 方案冻结与修订  engine.py 估计、敏感性、结论
               adjust.py 协变量调整        sources.py 读取与追加
               server.py HTTP 接口         cli.py 命令行
web/           单页界面
tests/         41 项分析与接口测试
```

运行测试：`python3 -m unittest discover -s tests -v`
